# AXORA Accessibility Baseline

Accessibility should be part of acceptance criteria, not a last-minute visual polish pass.

## Baseline
- Use semantic HTML and correct heading structure.
- Ensure keyboard access to all interactive features and provide visible focus.
- Label form fields and make validation errors clear to assistive technology.
- Provide useful alt text for meaningful images; use empty alt text for decorative images.
- Maintain readable contrast, scalable text, and responsive layouts.
- Do not communicate status by color alone.
- Respect reduced-motion preferences and avoid flashing content.
- Provide loading, empty, error, and success states.
- Test at least one keyboard-only flow and the most important mobile-size layout.

## Before release
- [ ] Main user journey can be completed by keyboard
- [ ] Form controls and error messages have accessible names
- [ ] Focus order and focus visibility make sense
- [ ] Contrast and zoom/reflow have been checked
- [ ] Motion and status cues have alternatives
- [ ] Manual assistive-technology review considered according to risk
