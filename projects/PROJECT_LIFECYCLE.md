# AXORA Project Lifecycle

Use the stages below to keep portfolio status honest and comparable.

## Stages and exit criteria

### 1. Idea
- Problem and target user stated.
- Initial assumptions identified.
- No claim of validated demand.

### 2. Discovery
- User/problem research conducted where practical.
- Alternatives and existing workflows reviewed.
- Major technical, privacy, cost, and adoption risks listed.
- A small validation experiment chosen.

### 3. Prototype
- One core user journey works end-to-end.
- Known limitations visible.
- Tests and setup instructions exist.
- No unsupported production or security claims.

### 4. Beta
- Limited users can test the product safely.
- Feedback and issue-reporting path exists.
- Data access, privacy notice, rate limits, and support responsibilities are defined.
- Rollback path is documented.

### 5. Production
- Acceptance criteria and required tests pass.
- Security/privacy review appropriate to risk completed.
- Monitoring, support owner, backups, recovery, incident handling, and rollback are operational.
- Release notes, terms/consents where applicable, and data retention/deletion behavior are documented.
- Costs and service dependencies are understood.

### 6. Paused or retired
- Status and reason recorded.
- Users/operators informed where necessary.
- Data export/deletion and service shutdown handled safely.
- Credentials and unused resources revoked or removed.

## Portfolio review cadence
Review active projects periodically based on available time and risk. Record last reviewed date, next milestone, current blocker, and whether to continue, pause, or stop. Do not keep a project marked active only because work has already been invested.
